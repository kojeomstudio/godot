# AGENTS.md

Guidance for ZCode agents working in this repository.

## Repository

Godot Engine (4.7.x stable) — 2D/3D cross-platform game engine written in C++, built with SCons + Python tooling. Windows host (Git Bash); default build output goes to `bin/`.

## Directory map

- `core/` — foundation: Object/Variant system, containers, strings, math, IO, OS, extensions API
- `scene/` — scene tree, nodes, resources (built on `core/`)
- `servers/` — server interfaces (rendering, physics, audio) between `scene/` and `drivers/`
- `drivers/` — backend implementations (graphics APIs, audio, fonts)
- `editor/` — the editor; only compiled when `target=editor`
- `main/` — entry point and main loop
- `modules/` — optional statically-linked modules (gdscript, mono/C#, gltf, jolt_physics, …); toggle with `module_<name>_enabled=no`
- `platform/` — platform ports (windows, linuxbsd, macos, android, ios, web)
- `thirdparty/` — vendored external code. **Never modify or reformat**; excluded from lint/clang-format/mypy
- `tests/` — doctest-based unit tests (`tests/core/`, `tests/scene/`, `tests/servers/`)
- `doc/` — class reference XML (`doc/classes/*.xml`) exposed to scripting APIs
- `misc/` — build/utility scripts (many static-check hooks live in `misc/scripts/`)

Layering: `core` ← `scene`/`servers` ← `editor`. Core must not depend on scene/editor.

## Build

```bash
scons                                   # editor build → bin/godot.windows.editor.x86_64.exe
scons target=template_debug             # export template debug
scons target=template_release
scons dev_build=yes                     # faster dev iteration, debug features
scons tests=no                          # skip unit-test code (tests included by default)
scons -j<N>                             # parallel jobs
```

On Windows, the `.console.exe` variant attaches to the terminal (use it for CLI/stdout); `*.mono.exe` variants include the C# module. Do not edit files matching `*.gen.cpp|*.gen.h` or `modules_enabled.gen.h` — they are generated by the build.

## Tests

Tests must be compiled in (default). Requires a rebuild after engine changes:

```bash
bin/godot.windows.editor.x86_64.console.exe --headless --test --force-colors   # all unit tests
bin/godot.windows.editor.x86_64.console.exe --headless --test --help           # filter options
```

- Framework: doctest via `tests/test_macros.h`. Register new suites in `tests/test_main.cpp`.
- Scaffold a new test file: `python tests/create_test.py <PascalCaseName>`.
- Test data lives in `tests/data/`; make tests headless and deterministic.

## Static checks / lint / format

CI (`.github/workflows/static_checks.yml`) runs prek (pre-commit) over changed files. Hooks: clang-format (C/C++/GLSL/Java), ruff + mypy (all Python incl. `SConstruct`/`SCsub`), codespell, plus repo-specific hooks (file format, header guards, copyright headers, include validation). Run locally:

```bash
prek run --files <changed files>     # or: pre-commit run --all-files
clang-format -i <files>              # must match Godot .clang-format
```

Notes:
- New `.cpp/.h` files need a Godot copyright header (`misc/scripts/copyright_headers.py` checks) and Godot-style include guards (`misc/scripts/header_guards.py`).
- clang-tidy hook is manual-stage only and needs `compile_commands.json`; not part of routine checks.
- Python: ruff line-length 120, py39 target, isort config in `pyproject.toml`.

## API documentation & compatibility (CI-enforced)

- Any change to methods/properties/signals exposed to scripting **must** update `doc/classes/*.xml`. Regenerate with `bin/godot.<...>.console.exe --headless --doctool`, then fill in descriptions; `git diff` must be clean afterward.
- GDExtension API changes are validated against `extension_api.json` (`misc/scripts/validate_extension_api.sh`).

## Conventions & gotchas

- Code style: https://contributing.godotengine.org/engine/guidelines/cpp_usage_guidelines (all contributions must follow it).
- Commits: imperative title < 72 chars, area prefix when useful (e.g. `Core: Fix ...`); one topic per PR.
- SCons cache and `.sconsign` live outside the tree; incremental builds are reliable — don't `git clean` to fix builds.
- The mono/.NET module has its own build (`modules/mono/build_scripts/build_assemblies.py`) and .NET tests (`dotnet test modules/mono/editor/Godot.NET.Sdk/Godot.SourceGenerators.Tests`).
- `__pycache__` dirs and `.gen.*` files are build artifacts — never commit them.

## Read before touching sensitive areas

- Build system changes: `SConstruct`, `methods.py`, `platform_methods.py`, per-dir `SCsub` files, `*__builders.py`.
- CI behavior: `.github/workflows/*.yml`, `.github/changed_files.yml`.
- CONTRIBUTING.md — PR/commit/test/documentation expectations summarized above.
